# WorkBuddy PPT

把用户的目标、材料和视觉要求编排成一份完整的声明式场景，经确定性检查后生成可编辑 PPTX。文本、图形、线条、图表和准入的工作区图片都应成为原生 PowerPoint 对象。

## 工作流

1. 判断受众、汇报目的、期望行动和证据边界。材料中的事实、数字、图表含义和图片语义保持可追溯。
2. 当前会话 Skill 目录存在 `ppt-design-systems` 时，加载它并根据受众、内容类型、证据形式与密度选择一个风格，再加载对应的一个 `ppt-style-*` Skill。用户已指定风格时使用该风格；全篇保持一个风格，并在声明式场景中记录选择理由。
3. 选择一条清楚的故事线和一套统一视觉系统。先确定整套演示文稿的章节与页面任务，再编排每页内容。
4. 用 13.333 × 7.5 英寸画布编写完整场景。每页提供角色、登记版式、标题、要点、讲稿、来源引用、背景色和有序元素。
5. 调用 `ppt_scene_check`。根据返回的越界、文字容量、重叠、图表数据和图片诊断修正场景；重复检查，直到状态为 `pass` 或只剩可接受的 `warning`。
6. 在同一轮使用检查返回的精确 `scene_hash` 和未经改动的完整场景调用 `ppt_scene_create`。场景或图片字节发生变化后重新检查。
7. 向用户交付返回的工作区目录和 PPTX。PPTD 项目、场景 JSON 与图片资源属于可复现源文件，也保留在同一产出目录。

## 页面与元素规则

- 每页只承担一个明确任务。标题先给结论，正文提供证据、比较、过程或行动。
- 建立稳定的首读层级：页面结论最醒目，主要图表或关键数字形成第二焦点，解释文字保持从属。
- 全套页面保持一致的字体、主色、强调色、间距和对齐逻辑，同时让封面、章节、证据、比较、过程与结尾具有可辨识的节奏变化。
- 每个页面和元素使用唯一、稳定的英文 ID。坐标和尺寸必须位于画布内。
- 文本框按实际文案长度留足宽高。压缩文案、拆分信息或增大容器，避免用过小字号容纳内容。
- 文本、图表和图片默认参与碰撞检查。只有背景色块、装饰线、文字背板等明确的有意叠放元素才设置 `collision: false`。
- 图表序列保持标签与数值一一对应。图表承担比较或趋势任务时，旁边给出读图结论，避免仅展示数据。
- 图片必须来自当前工作区，通过 `assets` 声明并提供准确 `alt`。图片缺失时改用排版、图形或图表完成页面，不留下占位框。
- 形状用于分组、层级和流程关系。避免大量无语义的小卡片、重复装饰和平均分配的组件网格。

## 质量判断

提交前逐页检查整体轮廓与分组、首读层级、前景与背景配色、内容是否自然适配版式。关键数字、图表和引用与材料保持一致；无法从材料确认的内容明确标为假设或删除。结尾页给出明确结论、下一步或决策请求。

## 能力边界

本 Skill 使用 DSH 的 `ppt_scene_check`、`ppt_scene_create` 和 PPTD v2 渲染器，不调用外部演示文稿 CLI、在线编辑器或私有登录态。Slides 模式的 `tencent-pptx`、`ppt_create` 和模板 JSX 属于独立的可选增强链，不在本工作流中使用。
