# 架构

[English](ARCHITECTURE.md) | 中文

`dsh-workbuddy-ppt` 是一个可安装 DSH bundle，提供两条明确执行链路。两条链路共享产品基础设施，并保留各自的创作与渲染约定。

## 包组成

```text
dsh.bundle patch
  -> Host 插件
     -> 会话归属的 OfficePptService 与存储
     -> 受治理的演示文稿工具
     -> 包内 Skills 与模板参考
     -> 可选的受管 Slides 运行时
  -> Web 客户端
     -> PPT / Slides 输入模式
     -> 模板选择
     -> 最终文件预览与交付操作
  -> dsh-pptd CLI
     -> convert / inspect / check / screenshot / render
```

插件包负责配置和注册；DSH 继续负责会话、工作区、审批、审计、凭据、子进程策略和浏览器/Host 传输。

## 默认 PPT 链路

```text
请求与资料
  -> 包内 Kimi-compatible Skill
  -> 完整声明式场景
  -> ppt_scene_check
  -> 精确 scene_hash 回执
  -> ppt_scene_create
  -> 序列化 PPTD v2 项目
  -> 共享解析器与检查器
  -> 原生可编辑 PPTX 渲染器
  -> 原子发布到工作区
```

回执覆盖标准化场景数据和准入图片哈希。生成工具在同一轮重新计算回执；场景或图片发生变化时，旧回执立即失效。PPTD 同时是渲染器输入和保留的源产物，校验与渲染不会悄然消费两份不同项目。

渲染器创建可编辑文本、图形、线条、表格、图表和受限图片，不启动 SlideP、Tencent Docs 或其他演示文稿服务。

## 可选 Slides 链路

```text
请求与资料
  -> 同轮 Tencent PPT Skill 回执
  -> 选中模板语义索引
  -> STORY + DESIGN + 受限 JSX 页面
  -> 模板保真与代码检查
  -> 受管 SlideP 页面校验
  -> 受管 Tencent Docs 首轮同步渲染
  -> 不可变修订版与工作区原子交付
```

可选运行时由操作者提供并装配到插件根目录下。DSH 通过受治理的 subprocess 服务启动进程，把编辑器限制在回环地址内，约束诊断输出与时限，并在插件卸载时等待进程退出。

## 共享状态与交付

- 活动 DSH 会话决定工作区，调用方不选择存储或交付根目录。
- 内部项目状态、不可变修订版和可见工作区交付目录相互独立。
- 工作区图片经过真实路径、扩展名、文件签名、大小和哈希检查。
- 完整交付目录进入最终名称后，服务才发布会话状态。
- 浏览器预览通过回环 RPC 读取持久化的最终 PPTX，不接收引擎地址、Host 存储键和本地运行时路径。

## 扩展边界

- 生图由独立 DSH Provider 与工具提供，本包消费生成后的工作区素材。
- 视觉理解由当前会话选择的对话模型负责。
- 设计系统文档保持为操作者装配的本地输入。
- PowerPoint 与 WPS 是下游原生应用验收目标。
- 新渲染器必须消费经过校验的中间表示，并复用同一套会话、策略、审计和交付服务。
